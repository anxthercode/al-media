**Приоритет:** корректный end-to-end сценарий (от вставки ссылки до корректного файла) → самостоятельная Windows-сборка → устойчивость и тесты → полнота функций → полировка UI. Не скрывать недоработки ради красивого отчёта.

## 1. Цель и поддерживаемая платформа

Приложение **AL Media** (`ALMedia.exe`) — современный графический загрузчик разрешённых пользователю видео и аудио с платформ, поддерживаемых `yt-dlp` (YouTube, TikTok, Instagram, VK, RuTube и др. **при условии, что соответствующий extractor работает**).

**Основная платформа:** Windows 10/11, x64. **Язык по умолчанию:** русский; также английский и украинский. **Формат дистрибутива:** обычный Windows setup `.exe` с ярлыками, удалением и standalone portable ZIP. Конечному пользователю **не нужно** устанавливать Python, Qt, запускать IDE, использовать командную строку или вручную ставить `yt-dlp`, FFmpeg и Deno.

Интерфейс должен запускаться офлайн; для загрузки контента, обновлений и получения метаданных требуется интернет. **Нельзя гарантировать поддержку любого сайта навсегда**: при изменениях платформ нужны обновления движка, а приватные/DRM/геоограниченные материалы могут быть недоступны.

### Принципиальные ограничения

- Не пытаться обходить DRM, платежи, закрытый доступ, авторизацию без разрешения или защиту аккаунтов. Соблюдать законы и условия использования сервисов. Не обещать скачивание защищённых потоков.
- Не запускать пользовательские ссылки как shell-команды: **никакого `shell=True`**, `os.system`, конкатенации команды из URL.
- Не хранить cookies или логины в логах, не передавать их третьим лицам, не отправлять телеметрию без согласия.
- Не заявлять «100% без ошибок»; цель — проверяемая, предсказуемая работа с диагностикой и исправляемыми сбоями.

## 2. Зафиксированный технологический стек

- **Python 3.12** (для разработки; упакован в приложение при сборке).
- **PySide6 / Qt Widgets** — нативный desktop UI; виджеты создавать программно, использовать `QSS`, `QStackedWidget`, `QSplitter`/layouts; не требуется Qt Designer/Qt Creator.
- **yt-dlp** — **официальный отдельный Windows executable `yt-dlp.exe`**, вызываемый через `QProcess`. Это принципиально: бинарник обновляется независимо от Python/Qt GUI. Использовать `-J`, `--print`, `--progress-template`, `--newline` и exit code; не разбирать нестабильный обычный текст прогресса regexp-ами как единственный способ.
- **FFmpeg + FFprobe** — отдельные бинарники из проверенного дистрибутива. Передавать `--ffmpeg-location` абсолютным путём.
- **Deno** — отдельный Windows бинарник поддерживаемой версии (ориентироваться на актуальные требования `yt-dlp`; на момент написания руководства EJS требует Deno от 2.3.0). Передавать путь через поддерживаемую опцию `--js-runtimes`, не зависеть от глобального PATH.
- **SQLite (stdlib)** — задачи, история, настройки схемы; миграции БД. `QSettings` или JSON для простых UI-предпочтений; не смешивать две конкурирующие истины.
- **PyInstaller --onedir --windowed** — дистрибутив Windows (при необходимости `.spec`). Не требовать именно `--onefile`: **one-dir надёжнее для сторонних бинарников и обновлений**.
- **Inno Setup** — установщик `.exe`, ярлыки, корректная деинсталляция.
- **pytest + pytest-qt + ruff** — тесты, smoke-тесты GUI и статическая проверка. GitHub Actions Windows CI.

Дополнительные зависимости только по необходимости. Указывать версии/совместимые диапазоны в `pyproject.toml`, фиксировать точные зависимости сборки lock-файлом либо воспроизводимой CI-конфигурацией. Не делать критический функционал зависимым от неочевидной внешней библиотеки.

**Почему не встроенный Python API yt-dlp:** после заморозки Python в `.exe` замена установленной pip-библиотеки обычно не обновляет уже собранный пакет. Отдельный проверенный `yt-dlp.exe` позволяет безопаснее обновлять движок без пересборки всего интерфейса.

## 3. Пользовательский опыт и дизайн

Сделать **реальный рабочий UI**, не скриншот, не HTML и не веб-сервер.

### Главное окно

- Нативная рамка Windows, заголовок **AL Media**, иконка приложения; начальный размер около `1200×780`, минимум около `900×600`, корректные DPI 100–200%, изменение размеров без наложений.
- Слева компактная панель: **Загрузки**, **История**, **Настройки**, **О программе**; активный раздел заметен.
- Сверху крупное поле URL с placeholder, кнопки **Вставить**, **Добавить**, drag-and-drop ссылок и `.txt` файлов UTF-8 (один URL на строку). Поддержать Ctrl+V и Enter.
- После добавления отображать карточку медиа: миниатюра (если доступна), заголовок, источник, продолжительность, автор/канал, URL, выбор режима/формата/качества, путь, статус. Пока метаданные запрашиваются, показывать **реальное** состояние «Получение информации…».
- Список задач: действия **Начать / Отменить / Повторить / Удалить из списка**, общий **Скачать всё**; для завершённых задач — **Открыть файл / Показать в папке**.
- Индикатор прогресса для каждой задачи: процент (если размер известен), загруженные байты, скорость, ETA, сообщения этапов «Загрузка», «Объединение/Конвертация», «Готово» или «Ошибка».
- Индикаторы состояний зависимостей в настройках: yt-dlp, FFmpeg, Deno и версии. Кнопка **Проверить/Обновить движок**.
- При отсутствии интернета приложение остаётся отзывчивым, сообщает об ошибке, позволяет смотреть историю/настройки.
- Современная **тёмная тема по умолчанию**: аккуратные отступы, спокойные контрастные цвета, согласованные состояния hover/disabled/focus, читаемый текст, единая система размеров. Светлая тема тоже обязательно. Не использовать обязательные сетевые шрифты, CDN или внешние ресурсы для рендеринга GUI.
- UI не должен зависать во время распознавания ссылки, скачивания, проверки обновлений, загрузки миниатюр или сохранения истории.

### Настройки

Путь для загрузок (по умолчанию системная папка «Загрузки»), выбор пути через системный диалог; одновременные загрузки `1..5` (default `2`); тема; язык `RU/EN/UK`; поведение при совпадении имени файла (безопасное добавление суффикса/политика yt-dlp); включение/отключение субтитров и языки; встраивание метаданных/обложки там, где формат поддерживает; прокси **не обязателен**; cookies — **по явному выбору пользователя** (см. раздел 6); проверять обновления при запуске (по умолчанию включена, с возможностью отключить).

Настройки должны сохраняться между запусками. Неверный путь, отсутствие доступа, недостаток места, слишком длинное имя или кириллица в пути не должны приводить к необработанному падению.

## 4. Сценарий загрузки (обязательно end-to-end)

1. Пользователь вставляет URL (http/https) или несколько URL в строки. Удалить лишние пробелы и пустые строки, отклонить явно некорректные значения. Не выполнять URL как shell-код.
2. Создать задачу с уникальным ID и статусом `pending_metadata`. Асинхронно вызвать официальный `yt-dlp.exe` с `-J --no-playlist` и корректными флагами (если выбран список воспроизведения — см. ниже). Установить таймаут на получение метаданных и корректно завершать зависшие процессы.
3. Считать **JSON** и доступные форматы. Отсутствующие поля (`title`, `duration`, `thumbnail`, `formats`) допустимы. Нельзя делать необоснованные предположения, что существуют 1080p/4K, MP3 напрямую или конкретный codec.
4. Дать пользователю выбрать:
   - **Видео:** «Лучшее доступное»; 2160p/1440p/1080p/720p/480p/360p **только когда доступны** (при необходимости трактовать пресет как верхний предел `height<=...`); MP4 **по возможности**, без ложной гарантии, что любой codec конвертируется без потерь.
   - **Аудио:** «Лучший исходный аудиоформат», MP3 128/192/320 kbps через FFmpeg, M4A (когда доступен). В интерфейсе отличать исходный битрейт от параметра перекодирования.
5. По кнопке «Скачать» задача переходит в очередь. Планировщик запускает не больше установленного числа **отдельных процессов** `yt-dlp` одновременно. Каждая задача имеет собственный `QProcess`, output/error буферы и собственный state machine.
6. Собирать аргументы через **список аргументов** процесса: `--no-playlist`, `--newline`, `--progress-template` для `download` и `postprocess`, `--ffmpeg-location`, `--paths`, `-o` и `-f`/`-x` и т.д. Стандартизированный прогресс делать парсируемым (маркер `ALM_PROGRESS:` + поля), тестировать parser на неполных/неизвестных значениях и раздельных строках stdout/stderr; не предполагать, что всегда известен `total_bytes`. **Не использовать `shell=True`**.
7. Загружать во временные/`.part` файлы на целевом диске, а финальным успехом считать только **exit code 0 + наличие фактического финального файла**. Для надёжного определения пути применить официальный `--print after_move:...` / поддерживаемый вывод, а не угадывать имя по title. Учитывать корректный output при playlist и postprocessing.
8. Кнопка «Отменить» корректно прерывает скачивание и дочернюю обработку. Не удалять уже существующие чужие файлы. При аварии сохранять `part` для поддерживаемого yt-dlp докачивания. **Не обещать универсальную паузу**; вместо этого «Отменить» + «Повторить/Продолжить, если сервер поддерживает».
9. При ошибке показывать краткую причину: неправильный URL, сеть/таймаут, extractor не поддерживается, доступ закрыт, cookies требуются, FFmpeg/Deno отсутствует, диск, postprocess, cancelled. Подробности — в логах **без утечки секретов**.
10. После успешной загрузки сохранять в историю URL, платформу, название, время, статус, путь и настройки качества, затем разрешать открыть файл/папку. Не считать «завершено» скачивание одного фрагмента до объединения потоков.

### Плейлисты

- Отличать единичное видео от плейлиста. По умолчанию URL «видео с параметром списка» обрабатывать как **одно видео** (`--no-playlist`).
- Для настоящего плейлиста предложить пользователю явно выбрать «Одно видео» или «Весь плейлист» после метаданных, сообщить оценку числа элементов и запросить подтверждение на большие списки (например, >100 позиций).
- Реализовать обработку плейлиста с индивидуальными задачами или единым отслеживаемым заданием с корректной историей; загрузка не должна запускаться самопроизвольно при вставке URL. При невозможности распознать список — информативная ошибка, а не зависание.

## 5. Конкретные состояния задач и постоянные данные

**Допустимые состояния** (явная enum/строки):
`pending_metadata`, `fetching_metadata`, `ready`, `queued`, `downloading`, `postprocessing`, `completed`, `failed`, `cancelled`, `interrupted`.

- Переходы валидируются; завершение процесса с кодом 0 **без результата** означает `failed` (если это не явно предусмотренный режим).
- SQLite DB в `%LOCALAPPDATA%/ALMedia/data/app.sqlite3` (portable режим — отдельный локальный каталог данных при включённом явном portable-флаге).
- При старте задачи, оставшиеся после аварии в `downloading`/`postprocessing`, переводить в `interrupted`, не притворяться, что фоновые процессы продолжают жить. Показывать «Повторить».
- Миграция schema_version через `PRAGMA user_version` или механизм миграций; операции параметризованы; SQLite не пишется одновременно из множества потоков без соблюдения ограничений подключения.
- Мягкое удаление из списка не удаляет скачанный файл; отдельная операция удаления файла — только с дополнительным подтверждением, **не обязательно**.
- Логи в `%LOCALAPPDATA%/ALMedia/logs/`, с ротацией и санитизацией токенов/cookies/частных query-параметров. В UI кнопка «Открыть папку логов».

## 6. Cookies, безопасность и приватность

- По умолчанию **никаких cookies**. Два явных режима: путь к Netscape cookies.txt (`--cookies`) и «Читать cookies из браузера» (`--cookies-from-browser`, если поддерживается текущим движком/окружением). Не обещать, что любой браузер/профиль доступен.
- Не хранить содержимое cookies в приложении, не показывать его в логах/ошибках; в настройках хранить только согласованный пользователем путь и режим. Кнопка «Очистить настройки cookies».
- Не добавлять URL, заголовки авторизации, cookies и токены к telemetry/analytics. У приложения **нет** собственного сервера, аккаунта и обязательного облака.
- Обрабатывать небезопасные пути и имена; выпуск файлов — только в выбранную пользователем директорию. Не выполнять внешние команды из данных метаданных. Механизм открытия папки/файла использует безопасные Qt/OS API с проверенным путём.
- Сетевые обращения для обновлений и скачивания выполняются по HTTPS там, где их поддерживает источник; не выключать SSL/TLS проверку.

## 7. Управление бинарниками и независимое обновление yt-dlp

**Это обязательная часть, а не опция.** Главное GUI и загрузочный движок имеют разные жизненные циклы.

### Порядок поиска при запуске

1. Проверенная обновлённая версия `yt-dlp.exe` в `%LOCALAPPDATA%/ALMedia/bin/yt-dlp.exe`.
2. Проверенная исходная версия из `tools/` установленного приложения, поставляемая с Windows-дистрибутивом.
3. Системный `yt-dlp` — **только если пользователь явно разрешил альтернативный путь** (по умолчанию не нужен).

FFmpeg/FFprobe и Deno находятся в отдельной упакованной папке `tools/`; проверка выполняется через `-version`/`--version` с таймаутом. Путь с пробелами/Unicode должен работать. Нельзя писать обновлённый движок в `Program Files` без прав администратора.

### Получение/поставка зависимостей для сборки

- Windows build-скрипт получает **официальный `yt-dlp.exe`** из релиза `yt-dlp/yt-dlp`, плюс FFmpeg/FFprobe и Deno из указанных проверенных upstream-релизов. Для каждого файла/архива использовать pin версии и SHA-256 (либо проверенную контрольную сумму релиза); никаких скачиваний с неофициальных URL без согласованного источника.
- Проверять hash до распаковки/исполнения; если hash или TLS-проверка не совпали — **остановить сборку** с понятной ошибкой, без «аварийного обхода» проверки. Хранить URL, версию, hash и лицензии в `tools/dependencies.json` или аналогичном манифесте. Не класть огромные сторонние `.exe` в Git, если их воспроизводимо подтягивает сборка.
- **Не оставлять установщик без обязательных инструментов.** Итоговые installer и portable должны включать работающие yt-dlp, FFmpeg/FFprobe и Deno с notices. Если из-за лицензий/источников сборка невозможна, не помечать релиз готовым.
- Официальный `yt-dlp.exe` уже включает необходимые `yt-dlp-ejs` scripts, но для YouTube дополнительно нужен совместимый JS runtime. Проверить текущую документацию `yt-dlp` при реализации; не пытаться обойти отсутствие runtime отключением проверки.

### Обновление движка пользователем

- Кнопка «Проверить обновления yt-dlp» узнаёт последнюю **stable** версию из официальных GitHub Releases; network errors не ломают GUI.
- Сравнить версии, предложить обновление. Скачивать **только официальный Windows x64 артефакт**, verify SHA-256 по опубликованному файлу `SHA2-256SUMS` (по возможности проверить подпись sums при поддержке, документировать модель доверия). Не загружать исполняемый код с пользовательского URL.
- Скачивать в `.tmp`, убедиться, что hash верен, `yt-dlp.exe --version` запускается с таймаутом, только затем **атомарно переключать** активную версию (с бэкапом и rollback при сбое). Не заменять exe, пока есть активные загрузки: поставить обновление в ожидание/попросить остановить задачи.
- В интерфейсе показывать версии GUI/yt-dlp/FFmpeg/Deno и дату последней проверки. После перезапуска должна использоваться обновлённая версия движка без переустановки GUI.
- Не делать автообновление **самого GUI** в рамках MVP. Обновление yt-dlp не должно подразумевать тихую установку полной программы.

**Правила архитектуры:**

- UI не занимается сетевой бизнес-логикой/парсингом CLI. У ядра есть интерфейсы, которые можно мокать в тестах.
- `QProcess` работает асинхронно через Qt signals; изменения UI только из GUI-потока. У каждого процесса контролируемый lifecycle, callbacks не висят после уничтожения виджета.
- Все абсолютные пути и ресурсы корректно разрешаются как при `python main.py`, так и в frozen PyInstaller build (`sys._MEIPASS`/путь приложения использовать по назначению; пользовательские данные — всегда в user-data).
- Запуск не требует административных прав. При обычном закрытии окна все активные процессы корректно завершаются после диалога подтверждения. Встроенной скрытой фоновой службы нет.
- Упакованное приложение не зависит от случайного `yt-dlp`, `ffmpeg` или `deno`, оказавшегося в PATH.

## 9. Ошибки, крайние случаи и доступность

Обработать и покрыть тестами минимум:

- пустая/неправильная ссылка; несколько ссылок и дубликаты;
- плейлист и одиночный URL с параметром playlist;
- приватный, удалённый, неподдерживаемый, геоограниченный ролик;
- ошибка DNS, пропавший интернет, таймаут, 429, rate limits; сообщение без обещания обхода ограничений;
- отсутствие метаданных, thumbnail, форматов, duration;
- формат без видео/аудио, отсутствие нужного bitrate/разрешения;
- итоговый файл имеет другое расширение, чем входной поток; особые символы в названии;
- занятая папка, нет прав, диск переполнен, путь с кириллицей и пробелами;
- отсутствие/повреждение FFmpeg, Deno, yt-dlp; ошибочный checksum обновления;
- отмена во время метаданных, загрузки и конвертации; одновременное закрытие;
- повторное открытие после crash; прерванные загрузки и повреждённая БД;
- SQLite error и логирование без cookies/query token;
- адаптивная ширина при смене языка, длинные названия, scaling 150–200%; работа с клавиатуры.

Ошибку показывать пользователю в UI, а не только `print()` в консоль. Не использовать фразы «скачано успешно», если фактического файла нет.

## 10. Тесты и доказуемые критерии готовности

**Обязательные локальные проверки:**

```powershell
python -m pip install -e ".[dev]"
python -m ruff check .
python -m pytest -q
python main.py
```

GUI smoke-тесты запускать с `QT_QPA_PLATFORM=offscreen` в CI. В тестах вместо настоящего YouTube использовать **fake-engine**: управляемый процесс, который выдаёт предопределённый JSON, строки прогресса, ошибки и exit codes. Тесты не должны зависеть от состояния сторонних сайтов.

Минимальные acceptance criteria (все обязательны):

1. Двойной клик по `ALMedia.exe` открывает окно **без установленного Python и Qt**.
2. Нет чёрного консольного окна при обычном запуске GUI.
3. Тёмная/светлая темы и три языка работают, настройки сохраняются после закрытия.
4. Ссылка вставляется в очередь, metadata отображается без фриза GUI.
5. Форматы/разрешения отражают реальную доступность; неизвестная информация не ломает UI.
6. Фоновая очередь ограничена настройкой concurrency, задачи не перемешивают прогресс.
7. Работают MP4/video, аудио-only и MP3-конвертация при наличии соответствующих потоков и возможностей FFmpeg.
8. Progress/ETA показываются корректно, если известны, и «—», если данных нет.
9. Отмена завершает относящиеся к задаче процессы, не удаляя пользовательские данные.
10. История переживает рестарт; файл действительно существует перед `completed`.
11. Unicode/пробелы в папке работают; cookies не появляются в логах.
12. Отсутствующий инструмент диагностируется; UI не падает.
13. Обновление yt-dlp проверяет SHA-256, rollback при ошибке, не требует переустановки GUI.
14. Параллельные задачи, metadata, JSON parser, CLI-аргументы, БД и update flow покрыты автоматическими тестами.
15. Windows CI собирает portable, `installer.exe`, публикует их как workflow artifacts и запускает тесты.
16. Установщик ставит ярлык, запускает приложение без CLI, деинсталлятор удаляет установленные файлы **и не удаляет пользовательские загрузки**.
17. В portable/установщике **сразу включены** инструменты `yt-dlp.exe`, `ffmpeg.exe`, `ffprobe.exe`, `deno.exe`, а лицензии/источники документированы.

**Дополнительный релизный ручной тест на чистой Windows 10/11 VM:** без Python/Qt/Deno/FFmpeg из PATH установить программу; проверить запуск, версии инструментов, добавление URL, разрешённую тестовую загрузку (если сеть/сайт позволяет), открытие файла, обновление движка, uninstall. Если нет Windows-машины, **не утверждать**, что этот тест прошёл.
